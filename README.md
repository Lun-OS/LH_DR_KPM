### 功能描述

驱动提供内核级操控能力，覆盖进程内存、输入、传感器、进程可见性、调试与数据采集等多个维度，主要功能包括：

- **内存读写与扫描**：支持手动 ARM64 页表遍历，提供物理内存直读（DMA/WB 双路径）、批量读取、内核空间安全读取；支持多种数据类型与模式的扫描（精确、范围、变化、增减等），以及指针链扫描和内存冻结（周期回写锁定值）。
- **触摸注入与拦截**：维护虚拟触摸池，支持多点触控、像素/硬件最小单位坐标，具备操作保活与超时自动释放；拦截模式支持坐标重定向、偏移、镜像、固定等，可无缝融合真实与虚拟触摸。
- **陀螺仪与传感器控制**：通过内核 uprobe 挂载系统服务中的传感器事件转换函数，或通过 syscall tracepoint 拦截传感器读取，实现陀螺仪/加速度等数据的锁定、偏移叠加，支持硬锁与虚拟力叠加。
- **进程隐藏与反检测**：提供纯数据级 PID 摘除（默认）与 `/proc` 直连拦截（可选，默认关闭）两条回退链，实现进程从枚举、`ps`、`kill` 等途径隐藏，且不修改进程自身运行状态。
- **断点调试与寄存器篡改**：基于硬件断点与 perf 事件，支持内存断点、命中异步通知、命中时一次性覆写目标线程寄存器（GP/FP/PC/PSTATE），以及单步执行控制。
- **进程与模块枚举**：可遍历进程列表（完整命令行）、内存映射、模块基址与路径，支持按名称查询进程或模块信息。
- **ELF dump 与流式传输**：支持对目标进程模块进行 ELF 解析与分段 dump（含 CRC/SHA256 校验），并通过 UDP 流式数据报高效传输大块数据。
- **通用通道**：所有公共命令可通过 UDP（设备内局域网）或 prctl（root 进程）双接口调用，语义一致；UDP 特有命令（扫描状态、文件读取、dump、流式等）仅在 UDP 通道可用。

### 特点

- **隐蔽性分级管理**：功能按可检测性分为 A/B/C 三级，核心操作（内存读写、扫描、指针链、触摸注入、陀螺仪控制、进程隐藏默认路径等）均为 A 级，仅依赖内核标准机制或纯内存操作，非 root 不可检测；用户态 hook 已整体移除，杜绝持久残留向量。
- **全符号运行时解析与多级回退**：所有内核符号通过 kallsyms 惰性解析，关键能力（VMA 遍历、物理映射、内核拷贝等）均带多级回退链，任一符号缺失自动降级，全部缺失才禁用，不引发 panic。
- **双接口统一协议层**：UDP 与 prctl 接口共用同一套通道无关上下文与分发逻辑，新增公共命令只需在协议层添加一个分支，双通道自动获得；UDP 特有的大数据/推送命令留在接口层本地处理。
- **严格的生命周期与稳定性保障**：内存访问全程持有 mm 引用，内核读统一使用页级容错拷贝；卸载时序固定（先排空在途命令再释放资源），触摸与陀螺仪支持空闲自动释放，避免残留；自旋锁与计数排空替代 RCU 等待，降低卸载风险。
- **明确的功能边界（hook 口径）**：驱动不擅自 hook 用户态目标进程，仅允许 hook 系统/内核层（输入事件、syscall、uprobe/tracepoint、procfs 查找层）或由客户端显式下令对用户态进程的操作；用户态函数 hook 已禁用并保留空壳。
- **易扩展的模块化设计**：执行层各能力以独立模块文件组织，协议层统一分发，扩展新命令或新模块只需遵循既定接口与初始化/卸载时序，不破坏现有架构。

### 设计架构

驱动采用**三层架构**，自上而下为执行层、协议处理层和双接口层，各层职责清晰、解耦。

- **执行层**：由多个独立模块组成，如内存读写（`LH_mem_rw`）、扫描/冻结/指针（`LH_mem_scan` 等）、触摸管理（`LH_touch`）、触摸拦截（`LH_intercept`）、陀螺仪（`LH_gyro`）、断点调试（`LH_debug`）、进程隐藏（`LH_hide`）、进程枚举（`LH_proc`）、符号解析（`LH_syms`）、dump（`LH_dump`）等。每个模块只提供 C 函数接口，不感知具体通信通道，也不直接依赖其他模块的内部符号，模块间协作通过命令协议完成。

- **协议处理层**：核心为 `kpm_cmd_dispatch`，维护通道无关的命令上下文（参数、请求数据、输出缓冲等）。该层负责统一分发所有公共命令到执行层，并通过统一出口（`kpm_cmd_out_write`）将结果写回对应通道（UDP 写入内核缓冲，prctl 拷贝到用户空间）。UDP 特有的大数据或推送类命令不在协议层处理，而由 UDP 接口层本地实现。

- **双接口层**：
  - **UDP 接口**：内核 socket 监听固定端口，接收客户端请求后翻译为协议层上下文；同时本地处理 UDP 特有命令，如扫描状态查询、AOB 特征传输、文件读取、dump 流式传输、触摸事件推送等。
  - **prctl 接口**：通过 hook 系统调用 `prctl` 实现，仅允许 root 进程调用，将用户参数翻译为协议层上下文；prctl 专用命令（如寄存器篡改窗口、按名称查询）保留在接口层处理。
